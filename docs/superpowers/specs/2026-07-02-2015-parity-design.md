# PyCon HK 2015 Astro Parity Design

## Goal

Rebuild the 2015 PyCon HK site as Astro-native pages that visually and behaviorally match the live `https://pycon.hk/2015/` microsite as closely as practical, down to typography, spacing, colors, route status, and page content. The 2015 implementation must not be a raw static-site copy. It should use Astro components, typed data, scoped 2015 styles, and Astro-managed image assets so the app remains smaller and images can be hashed, cached, and optimized by Astro.

Every live 2015 route discovered in the audit must exist locally with matching status, title, visible content, and visual treatment unless it is a legacy top-level route that semantically belongs to 2015. In that case, the canonical migrated route moves under `/2015/`.

## Architecture

Create a dedicated `website/src/years/2015/` module with:

- `data/` modules for navigation, homepage sections, sponsors, organisers, news links, basic info, schedule slots, topic details, venue/hotel pages, and photo/highlight content.
- `components/` for `Layout2015`, navbar/dropdowns, jumbotron, section headings, sponsor/logo groups, schedule tables, topic detail pages, content pages, and photo grids.
- `assets/` or adjacent source image imports for logos and photos that should pass through Astro image handling.
- One small scoped stylesheet for the 2015 microsite. The stylesheet should reproduce Bootstrap-era behavior and the live 2015 typography, but it should not import a full copied Bootstrap distribution unless a measured parity gap requires it.

The current generic `/2015/` highlight landing should be replaced with this 2015 microsite. The existing `/2015/photos/` route can still reuse the normalized legacy highlight/photo data, but its chrome should match the 2015 microsite instead of the generic `LegacyShell`.

## Rendering Model

Use Astro pages and `getStaticPaths()` for dynamic topic/detail routes:

- Homepage: `website/src/pages/2015/index.astro`.
- Section pages: concrete Astro pages under `about`, `schedule`, `sponsor`, and `venue`.
- Topic pages: a dynamic route under `/2015/schedule/topics/[slug]/index.astro` backed by a complete topic dataset, including the encoded Cantonese slug.
- CSS/JS-looking compatibility routes: implement as explicit routes or endpoints that return 200 and mimic live content/status closely. They are part of the strict contract because live returns 200 for them.
- Photos: `/2015/photos/` as the canonical 2015-owned route.

Navigation and in-page links must use the new `/2015/` route contract. External links such as Eventbrite, Bitly, Gitter, and OpenSource.hk should match live destinations unless they are broken only because of legacy encoding artifacts.

## Visual Parity Target

The rebuilt pages should match the live 2015 microsite, not the current PyCon HK design system:

- Bootstrap-like fixed-width container and responsive breakpoints.
- Live navbar structure, dropdown labels, ticket link placement, and mobile collapse behavior.
- Jumbotron/home hero with the 2015 logo, headline, tagline, event theme line, date, venue, and chat button.
- Body font stack, headings, link color, button styling, section spacing, horizontal rules, table styling, and footer treatment matching live.
- Sponsor and organiser logo sizing/layout matching live desktop and mobile behavior.
- Schedule and topic detail pages matching live content hierarchy and text flow.

Differences are acceptable only for browser rendering noise, unavailable third-party scripts, or Astro image output filenames. Visible layout, typography, content, and route behavior should be treated as regressions if they differ materially.

## Image And Asset Strategy

Prefer Astro-managed image imports for all 2015 logos/photos used by Astro-rendered pages. This keeps the app smaller than a copied static tree and lets Astro generate hashed/cacheable output.

Rules:

- Import key logos and photos from source-controlled files rather than referencing `/legacy-wp/uploads/...` directly where practical.
- Keep only the sizes actually used by 2015 pages.
- Preserve alt text from live/export where available.
- Do not copy full historical static directories into `public/`.
- For route compatibility where live exposes CSS/JS text paths, keep those text assets tiny and explicit.

## Verification

Add a 2015 parity verification script or Playwright workflow that compares local preview against `https://pycon.hk`.

Required checks:

- Build/check passes for the website app.
- Every required 2015 route returns the same status as live.
- Titles and primary heading/body landmark text match live for user-facing HTML pages.
- Desktop and mobile screenshot comparison against live for at least:
  - `/2015/`
  - `/2015/schedule/`
  - `/2015/schedule/topics/better-type-at-python/`
  - the encoded Cantonese topic route
  - `/2015/sponsor/`
  - `/2015/venue/`
  - `/2015/photos/`
  - one CSS-looking compatibility route
  - one JS-looking compatibility route
- Pixel diff artifacts must be generated with Playwright and written under `output/playwright/2015-parity/`.
- The diff report should include per-route screenshots for live, local, and diff, plus a JSON/Markdown summary of mismatch percentages.
- Pixel comparison should use desktop and mobile viewport sizes matching the existing audit convention. Small antialiasing noise is acceptable; large structural differences, wrong fonts, missing images, wrong nav collapse state, or large vertical offset are failures.
- Image output should be inspected to confirm key 2015 images are emitted through Astro-generated assets rather than broad public static copies.

## Risks And Mitigations

- Live content may include routes not in the current audit. Mitigation: crawl `https://pycon.hk/2015/` links before implementation and compare against the required route list.
- Pixel parity may expose small browser/font differences. Mitigation: focus pass/fail on structural and typography-level differences, with diff images retained for review.
- Recreating legacy Bootstrap behavior in scoped CSS may miss edge cases. Mitigation: build the homepage, schedule, topic, sponsor, venue, and photos pages first, then tune shared 2015 components from screenshot diffs.
- CSS/JS-looking trailing-slash routes are unusual in Astro. Mitigation: test route generation early and choose explicit route files or endpoints that preserve live 200 behavior.

## Out Of Scope

- Rebuilding 2016 or 2017.
- Exact preservation of obsolete third-party analytics execution.
- Keeping 2015-owned content only at top-level legacy routes.
- Copying the entire historical static site tree into `public/`.
